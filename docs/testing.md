# Testing

Run `node scripts/verify.mjs` once after a coherent change. It syntax-checks browser/tool modules, runs all tests, checks asset/catalog references, prohibits application-data network calls and retired auth/hosting paths in public assets, and rejects diary-state access from friends/links/sharing. Zero package dependencies are an explicit standalone constraint.

Core tests exercise real state transitions, recent-mission selection, partial completion, ratings, safe invalid-backup rejection, merges/idempotence and truthful compass values. UI tests dispatch the real handlers: unfiltered home surprise, preserved active progress, steps/reflection, escaped notes, favourites/traditions, concurrent diary records and persistence warnings.

Sharing tests cover canonical known-mission payloads, id-only native calls, browser Web Share, silent AbortError, other errors, successful/denied clipboard and selectable fallback. Unknown inputs invoke no capability; Friends does not access storage. Retired Telegram-contact CRUD tests are removed because the owner replaced that feature; equivalent privacy and stronger public-payload/cancel checks replace them without weakening diary tests.

Pages tests build a temporary deployment directory and inspect its relative asset graph; rendered output must have no retired auth/server dependency. They import the assembled app and open/share a known mission with an existing private diary, asserting no state writes, no data request and no note/old contact in fallback markup, no read/write/delete of retired contact storage and id-only native share requests. Unknown and legacy queries are ignored.

`node scripts/build-pages.mjs` produces the artifact separately. CI runs the same verifier/build and then deploys. Production proof requires the exact Actions run, HTTP/MIME and live-byte comparison, recorded in [changes](changes.md). Knowledge gates and a fresh knowledge-only reviewer check instructions/claims separately.

Manual limits: event harnesses are not a browser, accessibility audit or every-phone result. External-app availability, recipient choice and actual delivery remain user/device acceptance. No accounts were created and no message sent. Android instrumented tests inspect chooser intent/payload at runtime; this is narrower than sending through every messenger. System file-picker export/import remains a separate physical-phone check. [UX](ux.md), [operations](operations.md). Review when flows, storage, integration or evidence changes.
